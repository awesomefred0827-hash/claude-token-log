# Claude Code 토큰 절약 도구 직접 시험 기록

> 기록: fred.lee — 중국에서 OEM을 운영하는 한국인 · 마지막 갱신: 2026-10-15 · 시험한 도구 3개

깃허브에 올라온 Claude Code 토큰 절약 도구를 우리 작업 환경에 하나씩 붙여 보고 잰 기록입니다.
도구마다 ① 원래 어떻게 쓰고 있었는지 ② 같은 과제 15문항으로 시험한 숫자 ③ 그래서 넣었는지 뺐는지
④ 넣었다면 실제로 1·3·7일 써 본 숫자를 이어서 적습니다. 숫자가 늘었든 줄었든 그대로 둡니다. 방법은 [METHOD.md](METHOD.md).

> **English** — A running log of token-saving tools for Claude Code we tried ourselves: how we worked before,
> the 15-run test numbers, whether we kept or dropped the tool, and 1/3/7-day real-usage follow-ups for tools we kept.
> Raw numbers: [results.csv](results.csv).

## 지금 우리가 쓰는 방식 (현재 최선)

- 지금 실제 사용량: 하루 평균 비용환산 9,172만 토큰(입력 9,422 · 캐시생성 1,623만 · 캐시읽기 5.36억 · 출력 356만), 호출 4,629회, 호출 1회당 19,813 [2026-10-08~2026-10-14(7일)]

**일하는 방식**

- Claude Code 기본 설정 그대로 쓴다. 토큰 절약용 외부 도구는 아래 '쓰는 도구'에 적힌 것만 붙인다.
- 같은 일이 3번 넘게 반복되면(수집·변환·정리) Claude가 손으로 하지 않고 파이썬 스크립트 하나로 돌린 뒤 결과 요약만 읽는다.
- 하위 에이전트는 동시에 1개, 많아야 2개만 띄운다. 에이전트마다 새 대화를 열어 토큰을 몇 배로 쓰기 때문이다.
- 판단이 거의 없는 대량 작업은 가벼운 모델(Sonnet) 하위 에이전트에 한 덩어리로 맡기고, 설계·검토만 큰 모델이 한다.
- 파일은 통째로 읽지 않고 필요한 줄만 읽는다. 큰 결과는 대화에 붙이지 않고 파일로 저장한 뒤 요약만 본다.
- 대화가 길어지면 새 대화로 넘긴다(인수인계 요약만 가져감).

**쓰는 도구**

- 없음. 시험한 도구 중 지금 붙여 쓰는 것은 없다.

**안 쓰는 도구와 이유**

- caveman v3.1.0 — 시험에서 과제 비용 +10.9%. 출력은 12% 줄었지만 플러그인이 규칙·스킬 목록을 시스템 프롬프트에 약 2,900토큰 더 얹어 매 호출 입력이 늘었다.
- pxpipe v0.14.0 — 시험에서 과제 비용 +196.7%. 그림으로 바꾼 맥락(문자 10.5만~16.8만 자 → 그림 5~8장)이 원래 글자보다 토큰을 더 먹었다.
- rtk v0.51.0 — 시험에서 과제 비용 +7.1%. rtk 자체는 명령 출력을 62.6% 줄였다(48건, 8천 토큰). 하지만 줄어든 출력을 본 Claude가 명령을 더 돌려 대화 턴이 늘었고, 턴마다 맥락 전체를 다시 읽는 캐시읽기가 19% 늘었다.

## 1. caveman (v3.1.0) — 시험 뒤 뺐다

### ① 기존에 우리가 이렇게 쓰고 있었다

- 방식: Claude가 평소 말투(짧은 한국어 문장)로 답했다.
- 실제 사용량(시험 전 7일): 하루 평균 비용환산 8,219만 토큰(입력 7,023 · 캐시생성 1,350만 · 캐시읽기 5.16억 · 출력 274만), 호출 2,987회, 호출 1회당 27,513 [2026-09-28~2026-10-04(7일)]
- 같은 과제 15문항 기준: 과제 1회 평균 비용환산 44,592 토큰, 정답 15/15

### ② 이 도구를 시험했다

- 도구: [JuliusBrussee/caveman](https://github.com/JuliusBrussee/caveman) v3.1.0, 2026-10-05 시험
- 붙인 방법: caveman 플러그인(답변을 극단적으로 짧게 하는 말투 규칙)을 시험 세션에만 불러왔다(--plugin-dir).
- 시험 조건: rtk와 같은 고정 문제 5개 × 3회, 같은 기존 측정값과 비교. 한국어 품질(한글 비율·영어 섞임)도 정답 조건에 넣음.

| 입력 | 6 | 6 | +0.0% |
| 캐시생성 | 26,661 | 29,533 | +10.8% |
| 캐시읽기 | 92,220 | 107,407 | +16.5% |

| 걸린 시간(초) | 18.8 | 24.1 | +28.2% |

### ③ 결과

- 과제 비용이 +10.9% 바뀌었다(정답 15/15 → 15/15). 출력은 12% 줄었지만 플러그인이 규칙·스킬 목록을 시스템 프롬프트에 약 2,900토큰 더 얹어 매 호출 입력이 늘었다. 우리 답은 원래 짧은 한국어 한두 문장이라 더 줄일 여지가 거의 없었다(답 원문 비교 시 거의 같음).
- 결정: **뺐다.** 실제 작업 환경에는 넣지 않았다.

## 이 기록의 한계

- 시험 과제가 짧은 단발 작업 위주라, 긴 세션에서 효과가 나는 도구(맥락 압축·세션 기억 등)는 숫자가 다르게 나올 수 있습니다.
- 답변을 한국어로 받는 환경에서 잰 숫자입니다.
- 하루 실사용량은 그날 일의 양에 따라 크게 흔들려서, 실사용 비교는 하루 총량이 아니라 호출 1회당 비용으로 합니다.
